## v0.16.4 — 修「草图」勾选框点不动（mxGraph 样式值 number 陷阱）

**现象**：绘图面板「样式」Tab 的「草图」勾选框点了一瞬间就弹回未勾选，视觉上「无法勾选」。

**根因**（已在真实 `src/mxClient.min.js` 上实证）：`mxStylesheet.getCellStyle()` 解析样式串时对纯数值值做 `mxUtils.isNumeric(f) ? c[k]=parseFloat(f) : c[k]=f`，
所以 `sketch=1` 读回来是 **number 1**。而 `applyStyleToPage()` 写完样式会同步调 `drawPanel.refresh()`，
里面 `this.sketchCheck.checked = getPageStyle("sketch") === "1"` → `1 === "1"` 为 false → 刚勾上就被抹掉。
同一类 bug 还波及：阴影、圆角、虚线判定（永远显示实线）、水平书写方向、HTML 标签、锁定（FormatPanel 与右键菜单都失效）、翻转 flipH/flipV。

**修法**：
- 新增 `src/styleValue.ts`：`isStyleOn(v)` = `v === true || String(v) === "1"`、`styleIs(v, expected)`。写入侧仍写字符串 `"1"`（draw.io 互通）。
- 全仓 15 处 `=== "1"` / `=== "0"` 比对改走这两个函数（FormatPanel、DrawPanel、DrawioView、SketchRenderer）。
- `getPageStyle()` 返回类型改成 `string | number | null` 并在注释里标注陷阱；DrawPanel 里 `adaptiveColors` 加 `typeof === "string"` 守卫。
- 页内无图形时整图级样式无处可写：`applyStyleToPage()` 早退分支补 Notice（新 i18n key `diagram.styleNeedsShapes`），不再让控件静静弹回。
- 圆角按钮去掉点击里手动的 `classList.toggle("active")`，状态只由 `refresh()` 从模型回填，避免无图形时留下「已开启」假状态。

**验证**：tsc 通过；esbuild `--production` 通过；抽出 mxClient 里 `getCellStyle` 源码 + 桩离线跑，证明 `sketch/rounded/shadow/dashed/glass/html` 都是 number；产物内中英文案已打入；源码已无比对残留。

**顺带**：并行对同一文件发多个 Edit 会互相覆盖（当时 `toggleFlip` 那处改动被冲掉，靠收尾自查脚本才发现）→ 同一文件的编辑一律串行。

**版本**：manifest/package/versions 三处同步升到 0.16.4（0.16.3 是上一版草图渲染）。

## v0.17.0 — 草图改为「边整体歪斜」（用户砍需求，方案 C 极简版）

**用户反馈拍板**：看过原型后不要 A/B/C 那套弓形/拆笔/端部越界，原话「就是图形边框有点歪歪扭扭的样子即可」，
参考图二（`clipboard-2026-09-14T02-55-16-670Z-15f7ecc1.png`）是**边保持直线、整体被斜推**（平行四边形感），不是手绘曲线。
追问确认三项：歪斜幅度=**轻微**、范围=**图形+连线**、填充处理=**描边歪、填充平整**。

**关键认知：为什么旧实现做不到「歪」**
旧版对每个坐标**独立**随机 ±2.2px → 得到的是「毛边」（edge 仍笔直，只是锯齿轮廓）。
参考图要的是**整条边一起倾斜**，即相邻顶点的位移必须**相关**。随机独立位移做不到这一点。

**新算法（三层叠加，`vertexDelta()`）**：
1. **剪切场 SHEAR_AMP=1.6** —— `Math.sin(相位 + (vi / 波长) * 2π)`，沿顶点序号铺低频正弦。
   相邻顶点相位接近 ⇒ 一条边两端几乎同步移动 ⇒ 边整体倾斜；跨半波长后反向 ⇒ 上下/左右边相对收拢。
   这是「歪」的主力。
2. **低频随机 LEAN_AMP=0.8** —— 同一分组（`⌊vi/2⌋`）共享，打散剪切场的规律性，避免所有图形歪成同一形状。
3. **高频手抖 JITTER_AMP=0.7** —— 每顶点独立，让边不那么光滑。
- `SHEAR_WAVELENGTH=2.0`；`SHEAR_Y_WAVELENGTH_RATIO=1.6` —— x/y 用**不同波长**，否则图形退化成统一旋转，反而不像手绘。

**实测效果（150×75 矩形，20 组种子）**：平均倾角偏移 1.03°、最大 3.32°；40×40 方块 2.41°/6.23°；300×200 大矩形 0.42°/1.27°。
位移是**固定像素**（最大 ~2.9px），所以小图形相对更明显、大图形更稳 —— 与手绘一致。
形态分布：平行四边形（整体斜推）12 / 混合 10 / 梯形（收拢）2 —— 与参考图二的平行四边形观感一致，**不需要再改成梯形**。

**「描边歪、填充平整」的实现方式（重要）**：mxGraph 的矩形/椭圆等 shape **只有一个几何节点**，填充和描边共用它，
没法只改描边。所以对带 fill/stroke 的几何统一只做**坐标平移、不改尺寸**（`width/height/rx/ry/r` 一律不位移），
保证填充块与描边轮廓始终对齐、不露白边。要真正让填充也歪只能改填充路径，成本不值得。

**圆弧处理（踩坑）**：`A rx ry x-axis-rotation large-arc-flag sweep-flag x y` 是 7 个一组。
最初误按 `inGroup===1`（ry）跳过，导致 `A 30 20 0 1 0 60 0` 里把 `20`（ry）当 sweep 标志位丢掉、几何错乱。
正确判定是 **`g<=4` 全部原样保留**（rx/ry/rotation/两个 flag），只有 `g===5|6`（终点 x/y）参与位移，
且整条弧共享一个锚点 `"arc" + ⌊argCount/7⌋`，让弧整体倾斜而不散开。

**幂等性验证要点**：mxGraph 每次重绘都用**模型里的原始几何**重新生成 `d`（不是拿上次结果再抖），
所以只要种子只依赖原始几何，连续三次重绘结果完全一致 —— 不会「越抖越歪」。这条已写成断言。

**验证法**（脚本在 `%TEMP%/mxprobe/`）：
- `sketch-verify.js` —— 用 **`typescript.transpileModule`** 把 TS 源转成 JS 再 `vm.runInContext`（比正则剥类型注解稳，
  最初用正则清箭头函数返回类型 `: () => number` 没清干净，直接 SyntaxError）。29 项断言全过。
- `angle-measure.js` —— 用**倾角偏移（度）**度量，别用斜率：垂直边 Δx→0 时斜率会爆到 845/949，那是度量方式的问题不是 bug。
- `shape-survey.js` —— 抽样看形态分布（平行四边形 vs 梯形占比）。
- `verify-build.js` —— 版本三处一致 + 源码旧逻辑已移除 + 中文文案反转义后在产物中全命中（265 条）。

**原型**：`prototypes/sketch-wobble-preview.html` —— 与 `SketchRenderer.ts` 同算法的可交互预览（8 种图形、4 档参数滑杆、换种子、原始轮廓对照）。

**版本**：按视觉特性升级，Minor → 0.17.0（manifest/package/versions 三处同步）。

## v0.16.6 — 同一根因扩散到工具栏：**全量**排查所有自绘 `<button>`

**现象**：用户发来顶部工具栏截图（视图菜单 / 撤销 / 重做 / 缩放 / 适应 / 删除 / 清空 / 导出 / 保存），12 个按钮**全是**灰底圆角实心方块。与 v0.16.5 修过的页面栏是同一个根因，只是上次只修了用户指出的那一处。

**关键认知**：上次是「点对点修」，这次证明必须**全量扫描**。凡是 `createEl("button")` 造的真 `<button>`，单类名规则一律会被 Obsidian 的 `button:not(.clickable-icon)`（(0,1,1)）盖掉。

**扫描结果**：全仓 20 处 `createEl("button")`，去掉已修的 PageBar 3 处 + 工具栏 2 处，另有 **11 个类**同样中招：
`drawio-palette-header`、`drawio-palette-scratch-del`、`drawio-find-btn`、`drawio-find-btn-text`、`drawio-toolwin-close`、`drawio-layers-btn`、`drawio-layers-icon`、`drawio-tags-addbtn`、`drawio-tags-chipdel`、`drawio-text-edit-btn`、`drawio-text-edit-apply`。

**这次的提权手法改用「重复类名」而不是父级前缀**：`.drawio-layers-btn.drawio-layers-btn {}` → (0,2,0)。
理由：浮动面板（FindReplace / Layers / Tags / TextEdit / ToolWin）挂在 **body** 上且可被拖动，祖先链不稳定；`.drawio-editor-container` 只覆盖主视图内的元素。重复类名不依赖 DOM 结构，写一条就能用，且**对 hover / 状态类规则的书写顺序要求不变**（`:hover` 本身算 (0,2,0)，基础规则提到 (0,2,0) 后仍靠「后写覆盖」生效，现有顺序恰好都对）。

**逐条修的部分**（`styles.css`）：

## 新增 GitHub Actions 工作流（CI / Release / Version Check / BRAT Beta）

**背景**：仓库此前**没有 `.github/`**。关键前提：`main.js` 在 `.gitignore` 里（构建产物不入库），
所以发版用的 `main.js` 必须由 CI 现场构建 —— 这一点正好由 Actions 承担。

**产出**（4 个 workflow + 1 个共用脚本 + README 章节）：

| 文件 | 触发 | 作用 |
|------|------|------|
| `.github/workflows/ci.yml` | push main / PR / 手动 | `npm ci` → tsc 类型检查 → 生产构建 → 断言三件套产物存在 |
| `.github/workflows/release.yml` | 推 tag + 手动 dispatch | 解析版本 → 版本一致性守门 → tsc → 构建 →（手动触发时补 tag）→ `gh release create` 附三件套 |
| `.github/workflows/version-check.yml` | push/tag/PR/手动 | 只跑 `check-version.mjs`，不装依赖，很快 |
| `.github/workflows/beta.yml` | push main（commit msg 命中才跑） | `[beta]` → `<版本>-beta.<run_number>` 预发布；`[rc]` → rc 预发布并清理旧 beta 预发布 |
| `.github/scripts/check-version.mjs` | — | 三文件版本一致 + `versions.json` 条目 + manifest 合规（本地也能跑） |

**踩到并沿用既有教训的点**：
- **Node 版本选 22**：官方要求 ≥18，但 20 已在 2026-04 EOL。
- **`gh release create` 不能带 `--draft`**，否则 Release 是草稿、Obsidian 市场抓不到。
- **tag 不加 `v` 前缀**；release.yml 里仍做了一次 `${VERSION#v}` 容错剥除。
- 路径里没有 `npm`/`npx`，但托管 node 目录里**自带 npm**，用
  `node <node-dir>/node_modules/npm/bin/npm-cli.js install` 调用即可（沙箱内可用）。
- **`tail` 在沙箱里同样不存在**：`npm … | tail -5` 会因 `tail: command not found` 让整条管道报错，
  与 `rm` 短路是同一类坑 —— 别加管道。
- **YAML 校验脚本的断言又错了一次**（第三次同类）：用 `/--draft/` 扫 release.yml，命中的其实是
  「注意：不要加 --draft」这行**注释**。修法是先剥掉整行注释再做约定检查。
  → 再次印证：断言失败先怀疑断言本身。

**验证**：js-yaml 真解析 4 个文件 + 结构断言 + 把每个 `run` 块抽出来交 `bash -n` 做 shell 语法检查
（脚本 `.workbuddy/tmp/validate-workflows.mjs`，退出码 0）。`tsc -noEmit` 本地跑通（exit 0）保证 CI 不会一上线就红。

## v0.18.1 插件改名：`drawio-editor` → `drawio-studio`（2026-09-14）

### 起因

用户在 community.obsidian.md 提交插件时被拒：**「带有该 ID 的条目已经存在。查看现有条目…」**

### 根因（实证）

`drawio-editor` 这个 id 已被 **doge-liang** 的插件「**Drawio**」占用（repo `doge-liang/obsidian-drawio`，
v0.7.1，`isDesktopOnly:false`，2026 在架，`minAppVersion` 同为 1.4.0）。它的插件目录名就是 `drawio-editor/`。
官方规则（`references/obsidian-official-docs.md`）：**id 与 name 都必须全局唯一**；id 只能小写字母 + 连字符、
不含 `obsidian`、不以 `plugin` 结尾。

### 顺带发现的第二个冲突（用户选择「保持现状 + 只在 README 记录风险」）

该插件 `src/constants.ts`：

```ts
export const DRAWIO_VIEW_TYPE = 'drawio-file-view';
export const DRAWIO_FILE_EXT  = 'drawio';
```

即 `registerExtensions(['drawio'], 'drawio-file-view')` —— 与本插件 `main.ts:55` **争同一个扩展名**。
从本机 `D:\Program Files\Obsidian\resources\obsidian.asar` 原文复核（注意：asar 不在 `%APPDATA%`，在安装目录的 `resources/`）：

```js
// ViewRegistry：命中已注册扩展名 → throw
registerExtensions=function(e,t){for(var n=this.typeByExtension,i=0,r=e;i<r.length;i++){var o=r[i];
  if(n.hasOwnProperty(o))throw new Error('Attempting to register an existing file extension "'.concat(o,'"'))}…}
// Plugin：只是转发，无 try/catch
registerExtensions=function(e,t){var n=this;this.app.viewRegistry.registerExtensions(e,t),
  this.register(function(){return n.app.viewRegistry.unregisterExtensions(e)})}
```

→ 后果不是「功能缺一块」，而是**后加载的那个插件 `onload` 抛错、整个加载失败**。
按字母序 `drawio-studio` 排在 `drawio-editor` 之后，受害的会是我们。
